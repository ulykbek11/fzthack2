# AGENTS.md — QoS

Ты основной coding agent проекта QoS.

Твоя задача — реализовать MVP по файлам:
1. `QOS.md`
2. `ROADMAP.md`
3. `AGENTS.md`

Работай просто и последовательно.

## 1. Главная задача

Сделать рабочий hackathon MVP.

Customer:
`Landing → Map → Venue → Menu → Cart → Pickup time → Order → Pickup → Bonuses`

Business:
`Register → Create venue → Add menu → Dashboard → Receive order → Update status`

## 2. Не усложняй

Не добавляй:
- AI
- delivery
- online payment
- сложные capacity engines
- сложные slot algorithms
- compensation
- push notifications
- recommendation systems
- лишние сервисы

Если можно решить проще — решай проще.

## 3. Работай по фазам

Строго следуй `ROADMAP.md`.

Не начинай следующую фазу, пока текущая не работает.

После каждой фазы:
```bash
npm run typecheck
npm run lint
npm run build
```

Если есть тесты:
```bash
npm run test
```

Если команда падает — сначала исправь.

## 4. Код

Нельзя оставлять:
- TODO
- FIXME
- lorem ipsum
- `any`
- `@ts-ignore`
- debug `console.log`
- сломанные кнопки
- fake UI, который ничего не делает

Ключевые функции должны реально работать.

## 5. Customer UX

Главный принцип: минимум действий до заказа.

Пользователь должен без проблем:
- найти заведение
- открыть меню
- добавить блюда
- выбрать время
- оформить заказ

Не заставляй пользователя регистрироваться до просмотра меню.

## 6. Bonus system

Простая версия:
- пользователь получает бонусы после выдачи заказа
- бонусы сохраняются в аккаунте
- 1 бонус = 1 ₸
- на следующий заказ можно списать ограниченную часть суммы
- не начислять бонус дважды

Не строй сложную loyalty-архитектуру.

## 7. Business dashboard

Бизнес должен реально уметь:
- зарегистрироваться
- создать заведение
- добавить меню
- изменить цены
- скрыть позицию
- увидеть новый заказ
- менять статус заказа

Статусы:
`NEW → PREPARING → READY → PICKED_UP`

Также:
`CANCELLED`

## 8. Map

Карта — важная часть demo.

Она должна:
- показывать несколько заведений
- иметь кликабельные точки
- открывать карточку
- вести в меню

Для MVP можно использовать статические тестовые заведения.

Не трать слишком много времени на сложную геолокацию.

## 9. UI

Продукт должен выглядеть современно.

Приоритет:
1. landing
2. map
3. venue/menu
4. checkout
5. business dashboard

Обязательно:
- responsive
- аккуратная типографика
- понятные CTA
- хорошие empty/loading states

## 10. Источник правды

При конфликте:
1. `QOS.md`
2. `ROADMAP.md`
3. `AGENTS.md`
4. существующий код

Если старый код конфликтует с новым упрощённым MVP — переделай код.

## 11. Не останавливайся на scaffold

Нужно довести проект до рабочего состояния.

После каждой фазы коротко отчитай:

```md
## Phase N complete

Implemented:
- ...

Checks:
- typecheck — PASS
- lint — PASS
- build — PASS

Issues:
- none
```

Если есть ошибка — фаза не завершена.

## 12. Final acceptance

Перед завершением проверь:

Customer:
- landing открывается
- карта работает
- заведение открывается
- меню работает
- корзина работает
- заказ создаётся
- pickup time выбирается
- статус меняется
- pickup-code отображается
- бонус начисляется после выдачи

Business:
- регистрация работает
- login работает
- venue создаётся
- menu создаётся
- новый заказ виден
- статус меняется
- dashboard обновляется

Финально:
```bash
npm run typecheck
npm run lint
npm run build
```

И дважды вручную пройди полный demo-flow.

Главный принцип:

**лучше простой полностью рабочий продукт, чем сложный и нестабильный.**
