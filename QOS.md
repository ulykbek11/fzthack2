# QoS — Product Specification

## 1. Что мы строим

QoS — платформа предзаказа еды для кафе, ресторанов, кофеен и fast food.

Главная идея:

**Закажи заранее → приди → забери без очереди → получи бонусы.**

### Для пользователя
- не стоять в очереди;
- заранее оформить заказ;
- купить еду по цене самого заведения, без дополнительной наценки платформы;
- получить бонусы за использование предзаказа.

### Для бизнеса
- получать заказы заранее;
- уменьшать очередь у кассы;
- видеть входящие предзаказы;
- добавлять своё меню и управлять им;
- получать дополнительный канал продаж.

---

## 2. Основные части продукта

### 2.1 Лендинг

Главный оффер:

**Закажи заранее. Забери без очереди. Получи бонусы.**

На лендинге:
- hero;
- кратко проблема;
- как работает сервис в 3 шага;
- преимущества для пользователя;
- преимущества для бизнеса;
- CTA «Найти заведение»;
- CTA «Подключить своё заведение».

### 2.2 Карта заведений

Пользователь открывает карту в логике 2GIS.

На карте:
- рестораны;
- кофейни;
- fast food;
- столовые;
- локальные бренды.

У каждой точки:
- название;
- логотип;
- адрес;
- категория;
- открыто / закрыто;
- примерное время готовности;
- бонусы за предзаказ;
- кнопка «Открыть меню».

Фильтры:
- рядом;
- категория;
- открыто сейчас;
- время готовности;
- бонусы.

Для MVP можно использовать тестовые заведения и статические координаты.

### 2.3 Страница заведения и меню

Для каждой позиции:
- фото или визуальная карточка;
- название;
- описание;
- цена;
- категория;
- кнопка добавления в корзину.

Важно:

**Цена на платформе должна совпадать с ценой самого заведения.**

QoS не добавляет пользовательскую наценку на блюдо.

### 2.4 Корзина и оформление предзаказа

Шаги:

1. пользователь добавляет блюда;
2. открывает корзину;
3. выбирает время самовывоза;
4. подтверждает заказ.

На экране:
- состав заказа;
- количество;
- цена;
- итог;
- сколько бонусов получит пользователь;
- выбранное время;
- кнопка «Оформить предзаказ».

После оформления:
- номер заказа;
- статус;
- время получения;
- pickup-код или QR;
- количество будущих бонусов.

---

## 3. Бонусная система

**Пользователь получает бонусы за то, что оформляет предзаказ вместо того, чтобы становиться в физическую очередь.**

Это помогает:
- привлекать людей к платформе;
- формировать привычку пользоваться предзаказом;
- уменьшать очередь в заведении;
- возвращать клиента повторно.

### Простая механика MVP
- за каждый предзаказ начисляется фиксированное количество бонусов или небольшой процент;
- бонусы начисляются после выдачи заказа;
- 1 бонус = 1 ₸ скидки;
- использовать бонусы можно на следующем заказе;
- списать можно не более 20–30% суммы заказа.

Для MVP не нужна сложная геймификация.

---

## 4. Кабинет бизнеса

Бизнес регистрируется и создаёт своё заведение.

### Бизнес может
- указать название;
- загрузить логотип;
- указать адрес;
- выбрать категорию;
- указать часы работы;
- создать меню;
- редактировать цены;
- добавлять фото;
- включать и выключать позиции;
- видеть входящие предзаказы;
- менять статус заказа.

### Статусы заказа
- Новый
- Готовится
- Готов
- Выдан
- Отменён

### Dashboard
Показывает:
- новые заказы;
- заказы в приготовлении;
- готовые;
- количество заказов сегодня;
- сумму заказов сегодня;
- самые популярные позиции;
- количество выданных бонусов.

Главная ценность для бизнеса:

**Заказы приходят заранее, и бизнес понимает будущий поток до того, как клиент физически пришёл.**

---

## 5. Авторизация

### Пользователь
Для MVP:
- карта и меню доступны без входа;
- вход нужен только для бонусов и истории заказов;
- простой вход по номеру телефона / OTP.

Не делать:
- пароли;
- сложную регистрацию;
- большой onboarding.

### Бизнес
Для MVP:
- email + пароль;
- отдельная business-role;
- после входа пользователь попадает в dashboard.

## 8. MVP Scope

Обязательно реализовать:
- красивый landing;
- карта заведений;
- карточки заведений;
- страница меню;
- корзина;
- выбор времени;
- оформление предзаказа;
- статус заказа;
- pickup code / QR;
- бонусы;
- user auth по OTP;
- business auth;
- создание заведения;
- управление меню;
- business dashboard;
- статусы заказов;
- базовая аналитика.

---

## 9. Что НЕ делаем в MVP

Не добавлять без необходимости:
- delivery;
- курьеров;
- онлайн-оплату;
- AI/ML;
- сложную систему слотов;
- прогнозы загрузки;
- компенсации;
- сложный loyalty engine;
- push-уведомления;
- чат;
- отзывы;
- recommendation engine;
- production billing.

Главная цель — понятный и рабочий demo-flow.

---

## 10. Главный demo-flow

### Клиент
1. открывает landing;
2. нажимает «Найти заведение»;
3. видит карту;
4. выбирает ресторан;
5. открывает меню;
6. добавляет еду;
7. выбирает время;
8. оформляет предзаказ;
9. видит pickup-код;
10. получает бонусы после выдачи.

### Бизнес
1. входит в кабинет;
2. видит новый заказ;
3. нажимает «Готовится»;
4. нажимает «Готов»;
5. нажимает «Выдан»;
6. у клиента обновляется статус и начисляются бонусы.

---

## 11. Product message

**QoS помогает людям заказывать еду заранее и забирать её без очереди, а бизнесу — получать заказы ещё до прихода клиента.**

Клиент:
**меньше ждёт + получает бонусы.**

Бизнес:
**меньше очередей + больше предзаказов + заранее видит спрос.**
